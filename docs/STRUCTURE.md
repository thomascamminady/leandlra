# Core and catalogue

All Lean sources are below `LeanDLRA/`. They form two Lake libraries.

| | Core | Catalogue |
|---|---|---|
| Library | `LeanDLRA` | `LeanDLRACatalogue` (the core and everything else) |
| Root file | `LeanDLRA.lean` | `LeanDLRACatalogue.lean` |
| Build | `lake build` | `lake build LeanDLRACatalogue` |
| Content | one connected theory | results of single papers that are not stated in the core definitions |

**Core.** Every module outside the four folders `Literature`, `OpenProblems`, `Novel` and
`Corrections`, and the modules of these four folders that are listed in
[`promoted.txt`](promoted.txt). The root file `LeanDLRA.lean` lists the core modules; it is
generated by `scripts/gen_root.sh`, and `uv run -q scripts/core.py summary` prints the numbers of
modules of both libraries. The folders outside the four are, by layer and topic: `Foundations`,
`LinearAlgebra`, `Analysis`, `Matrix`, `FixedRank`, `DLRA`, `Integrators`, `Tensor`, `Dynamics`,
`Stability`, `Stiff`, `HighOrder`, `Randomized`, `Stochastic`, `Kinetic`, `Filtering`, `Control`,
`Training`, `Classical` and `Research`. Every core theorem is stated in the shared definitions of
the core ([CONCEPTS.md](CONCEPTS.md); the list of all definitions is
[DEFINITIONS.md](DEFINITIONS.md)), so core results can be combined with each other. Statements about
what the library provides refer to the core. The definitions of a topic are in its `Defs.lean`, or in
the `Defs.lean` of a subfolder where a topic has several: for example
`LeanDLRA/FixedRank/Defs.lean` has the tangent projector for given factors, and
`LeanDLRA/FixedRank/TangentSpace/Defs.lean` the tangent projector and the tangent space at a matrix
([CONVENTIONS.md](CONVENTIONS.md), sections 2 and 3).

**Catalogue.** The other modules of the folders `Literature`, `OpenProblems`, `Novel` and
`Corrections`. Each is a proven result, checked like the core (no `sorry`, standard axioms only), but
stated in definitions of its own file or of the paper it comes from. A catalogue theorem therefore
does not automatically apply to the objects of the core.

**Rule.** A core module imports core modules only. `scripts/core.py check` tests this; the gate and
CI run it.

**Promotion.** A catalogue module becomes a core module once its definitions are the core definitions
or are proven equal to them. Add its name to `docs/promoted.txt` (every module it imports must be in
the core) and run `scripts/gen_root.sh`, which writes both root files. The file itself does not move.
A module of the four folders is also listed in `docs/promoted.txt` when a core module imports it;
the comments of that file say which modules are listed for this reason.

## Imports

```lean
import LeanDLRA                              -- the core
import LeanDLRACatalogue                     -- the core and the catalogue
import LeanDLRA.Integrators.Matrix.BUGRun    -- one module, core or catalogue
```

## Checks

| Command | What it does |
|---|---|
| `make build` | writes the root files, checks the import rule, builds the core |
| `make verify` | `make build` and the axiom audit of the core (`scripts/audit.sh`) |
| `make catalogue` | builds everything with warnings as errors, audits the axioms of every constant, checks the recorded statements (`scripts/fidelity.py`), compares all statements with the gate's record (`scripts/rolling.py`) |

The gate (`scripts/gate.py`), through which every change of a Lean file reaches `main`, builds the
changed files and the core and audits both. It does not build the catalogue. A change of a core file
can therefore leave a catalogue module that no longer compiles; this cannot make a false statement
pass, because a module that does not compile proves nothing. The `Catalogue` workflow reports such
modules, and they are repaired or removed.

The gate keeps a record of the statement of every declaration (`scripts/rolling.py`). In every round
it compares the statements of the core and of the changed files with this record under the rename
map `docs/renames.json` (`scripts/hashdiff.py`) and checks the recorded statements. A change can be
queued with the number of statements it may change or remove; the round is rejected if it changes
more.

The recorded statements ([CONTRIBUTING.md](../CONTRIBUTING.md)) are in two files:
`docs/statements.json` for theorems of core modules and `docs/statements_catalogue.json` for those of
the catalogue; no name is in both. The gate and `scripts/fidelity.py` check both;
`scripts/fidelity.py --lib=LeanDLRA` checks the core file against the core library alone. After a
promotion, `uv run -q scripts/rolling.py records --write` moves the entries of the promoted modules
to the core file.

| Workflow | Trigger | Scope | Must be green |
|---|---|---|---|
| `lean_action_ci.yml` | every push | core: build with warnings as errors, import rule, audit, kernel replay of changed core modules | on every commit |
| `catalogue.yml` | push to `main` | everything: build with warnings as errors, audit, recorded statements unchanged, kernel replay of changed modules | before a release |
| `kernel_replay.yml` | nightly | `leanchecker` replay of every module | before a release |
| `certify.yml` | manual | everything: clean build, audit, replay, external checkers, signed `certificate.json` | for a release |

The API reference on the website covers both the core and the catalogue.

## Scripts

Each script of `scripts/` and each test of `tests/` names the library it serves in a comment near
its top: `Scope: core`, `Scope: catalogue` or `Scope: both`. Those for the catalogue alone are in
`scripts/catalogue/` (the full build `scripts/catalogue/catalogue.sh`, the connectivity report and
its inventory, the paper corpus and the literature slices) and `tests/catalogue/`;
`tests/test_script_scopes.py` checks the tags.

## Pages

The pages about the core are in `docs/`. The pages about the catalogue are in `docs/catalogue/`: the
local forms of the core notions in single papers (`docs/catalogue/CATALOGUE.md`, the counterpart of
`docs/CONCEPTS.md`), all modules with their sources (`docs/catalogue/PROVEN.md`, written by
`scripts/ledger.py`), `docs/catalogue/NOVEL.md`, `docs/catalogue/CORRECTIONS.md` and the literature
survey `docs/catalogue/survey/`.
